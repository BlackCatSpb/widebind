# Коллективный слой знаний: рождение и формализация концептов

> Статус: **проект (design)**. Механизм для эксперимента ПОСЛЕ baseline-запуска 86M.
> Отправная точка: `core/mirror.py` (private memory, cross-expert attention, contradiction gate) + ConceptMiner из EVA-Ai.

## 1. Идея в одном абзаце

В широком смысле это попытка дать модели **внутренний майнинг концептов**: механизм, который
находит в K-пространстве «семантические лакуны» (области, которых модель не знает) и
**материализует их как новые слоты** коллективной памяти. Слот — это прототип-вектор,
рождённый как центр открытого кластера, а не взятый из данных. Потом он «формализуется»
(уточняется EMA, набирает уверенность) и либо становится стабильным знанием, либо вымирает.

**Иерархия ролей (важно):**
- **Майнер** даёт *сущность* — предлагает прототип из лакуны. Не судит.
- **Декод-проба** подтверждает *формализацию* — но **только как проверка** (witness, не judge).
- **Судья — сама модель**: концепт реален, если его *использование* вознаграждается
  внутри её же динамики (см. раздел 5.2). Слово модели для суждения не нужно.

Аналог в биологии: система не только запоминает то, что встретила, но и активно ищет,
чего ей не хватает, и создаёт заготовки («фантомные концепты») под эти пробелы.

## 4. Дизайн: коллективный слой с рождением концептов

### 4.1 Потенциал занятости `U_s`

Каждый слот `s ∈ {1..S}` коллективной памяти имеет **EMA-счётчик занятости** (аналог
confidence в EVA):

```
U_s ← β_U·U_s + (1−β_U)·read_g_s          # read_g_s — читается ли слот в этом шаге
```

`U_s` — это потенциальное поле над K-пространством. «Сколько модель опирается на слот».
Параметры: `S = 8…16`, `β_U ≈ 0.99`.

### 4.2 Детектор лакун (novelty-сигнал)

Для текущего K-состояния эксперта `h_K`:

```
d_s = 1 − cos(h_K, m_s)          # расстояние до слота s
d_min = min_s d_s                # лакуна: насколько вход далёк от всего известного
```

Использование `d_min`:

- **write-бонус**: эксперт, попавший в лакуну, получает повышенный write-авторитет —
  он нашёл новую территорию (в EVA это «gap → приоритет майнинга»):
  `authority_g = conf_g · σ(κ·(d_g − τ_gap)) · (1 − contra_g) · social_pressure`
- **novelty-гейт**: `n_gate = σ(w_n·d_min + b_n)` — learnable сигнал в gate-арбитр
  (модель учится *решать*, обращать ли внимание на новое).

Порог `τ_gap` адаптивный, как в EVA: `τ = τ_base·(1 + variance_k·σ_d)`.

### 4.3 Рождение концепта (аллокация слота)

Фантом рождается не мгновенно — только при **устойчивом** существовании лакуны
(аналог `confirmations` в EVA):

```
счётчик N_gap:      # EMA-индикатор: токены попадают в одну и ту же дыру
N_gap ← β_N·N_gap + (1−β_N)·[d_min > τ]
рождение: N_gap > N_birth  →  аллокация слота m_new = centroid(cluster лакунных h_K)
```

Eviction при заполнении `S`: вытесняется слот с наименьшим `U_s` (аналог `archived`).
Рождение/вытеснение — дискретные события; выполняются `no_grad`, как существующие
записи в private memory (`mirror.py:385`).

### 4.4 Формализация (уточнение прототипа)

Рождённый слот уточняется к состояниям, которые его активируют:

```
m_s ← (1−α_c)·m_s + α_c·(среднее h_K, активировавших слот)     # EMA-формализация
влияние слота: w_s = σ(c·U_s − b)                              # слабые слоты мало влияют
```

Жизненный цикл возникает сам из EMA:
`provisional (U_s мало)` → `confirmed (U_s ≥ thr)` → `stable (устойчиво высоко)` →
`archived (evict при min U_s)`. Это непрерывный аналог EVA-жизненного цикла.

### 4.5 Декод-проба (формализация, только для проверки)

Токенизация детерминирована на двух уровнях: BPE-токенизатор (фиксированные merge-правила)
и Zeckendorf-коды (по теореме Цекендорфа код токена **единственен**, `core/embedding.py`,
`zeckendorf_codes`). Значит путь `вектор → readout → logits → token → текст` — определённая
функция, и прототип слота можно в любой момент декодировать в строку **без LLM**.

Проба — это **witness, не judge**:
- даёт нам, людям, читаемое «имя» концепта (интерпретируемость);
- ловит катастрофический шум (слот, чьё имя — не-слово);
- НЕ является критерием истинности концепта: вектор может быть осмыслен в K-пространстве
  при странном «имени» и наоборот.

Проверка «реальное слово»: декодированная строка из top-k должна быть в словаре (нужен
wordlist), низкая энтропия имени (уверенность) — усиление сигнала. argmax одной головы
слишком слаб — берём top-k.

### 4.6 Само-суждение модели (реальный критерий)

Модель понимает концепт не через слово, а через **использование**. Концепт реален, если:

```
(1) активация консистентна:  H(контекст, активирующий слот) мала
       → слот срабатывает на семантически связанных токенах
(2) вклад полезен:           loss(с гейтом слота) < loss(без него) на валидации
       → открытие гейта на слот улучшает предсказание
(3) занятость устойчива:     U_s монотонно растёт после рождения
       → стабильная сущность, а не вспышка шума
```

Выполнены (1)–(3) → `confirmed → stable`. Провал любого → `archived → evict`.
**Гейт-механика `σ(g_l)` — орган само-суждения**: модель открывает гейты на полезные
концепты и закрывает на мусорные. Слово для суждения не нужно.

## 5. Математика: почему это «аналитика потенциалов»

`U_s` — потенциальное поле. **Лакуна `d_min` — это `−∇_m U`** (направление к наименьшей
занятости). Рождение слота = **посадка нового бассейна в локальный минимум поля**.

**Условие открытия novelty-гейта** (то же, что для всех гейтов слоя):

```
гейт открыт ⟺ −E_t⟨∇L, m⟩ > λ_l1         # польза превышает cost разреженности
```

Гейт открывается только если сигнал *систематически* уменьшает loss; для избыточного
сигнала среднее внутреннее произведение → 0, гейт закрыт. Открытие «везде» — это
признак переобучения, режется `gate_l1`/sparsity-потенциалом.

**Контроль эхо-камеры** (чтение своих же записей):

```
m_{t+1} = (1−α+α·σ_eff·W)·m_t + ...     # линеаризация
устойчивость: ρ((1−α)I + α·σ_eff·W) < 1  # обеспечивается малым α + write-delay
```

**Предотвращение коллапса слотов** (все в один вектор): репульсия между слотами
(аналог `gate_repulse`/`div` в конфиге) + soft-competition записи.

**Аналитическое предсказание по глубине:** польза сигнала затухает через каскад
`∂L/∂h_L · Π f'_j`, поэтому ожидаем профиль `σ(g_l)`, **монотонно растущий с глубиной**:
глубокие гейты откроются первыми. Это измеримо.

## 6. Роль арбитра (кто-что пишет)

Арбитр (gate-механика `mirror.py:506-519`) в новой схеме получает три источника:

1. **contradiction** (уже есть) — эксперты *разошлись* по известному
2. **novelty / лакуна** (новое) — вход в *неизвестное*: `d_min`, `n_gate`
3. **концепт-граф** (уже есть) — `_concept_sim_ema` / `_behavior_div_ema` / `_trust_matrix`

Различие принципиальное: contradiction — конфликт в том, **что есть**; лакуна — **отсутствие**
того, чего нет. Оба — геометрические операции в K-пространстве, оба кормят один арбитр.

### 6.1 Интерфейс арбитр ↔ токенизатор

Токенизация детерминирована (BPE + Цекендорф-коды), поэтому арбитр получает точный,
воспроизводимый канал общения с языком. Три канала:

**1. Decode — верификация противоречий (лексика).** Арбитр формализует скрытые состояния
экспертов в слова «по требованию» — вторая, независимая точка зрения поверх геометрии:
- geometric disagreement (`mirror.py:329`) — эксперты далеки по косинусу
- **lexical contradiction** (новое) — декодированные слова экспертов реально конфликтуют
  (один тянет к «громко», другой к «тихо»)

**2. Encode — якорение/проба.** `слово → токенизатор → код → вектор`: вбросить известный
концепт как пробу или привязать рождённый слот к реальной лексеме.

**3. Birth-verify.** Рождённый слот → декод → словарьное слово → кандидат на самокуррикулум.

**Ограничения (иначе ломается обучение):**
- декод — строго `no_grad` / detached, по событиям (рождение, high disagreement), не на каждый токен
- в арбитр попадает **скаляр** (напр. «декод-противоречие подтверждено: 0/1», «имя слота —
  реальное слово: 0/1»); геометрия учится градиентом, лексика только подтверждает
- самокуррикулум — отдельный спарсный словарно-проверенный этап

### 6.2 Экспертный слой концептов (концепты + связи со знаниями слоя)

Отдельный слой экспертов-концептов — «дом» для рождённых концептов и их связей с текущим
знанием слоя. Три объекта:

```
M   ∈ R^{S×k}       # концепты-прототипы (рождённые, формализованные токенизатором)
G_k ∈ R^{S×G}       # связи концепт ↔ эксперт: кто из экспертов «знает»/несёт концепт
C   ∈ R^{S×S}       # граф концепт ↔ концепт: какие концепты сопряжены
```

Динамика (все — EMA/no_grad, как private_mem):

```
активация: a_s = softmax_s(−d(h_K, m_s))                # о каком концепте «говорят» эксперты
запись:    m_s ← (1−α_c)·m_s + α_c·(среднее активирующих h_K)   # формализация/уточнение
связи:     G_k[s,g] ← EMA(коактивация s × эксперт g)    # кто несёт концепт
           C[s,s']  ← EMA(коактивация s и s')           # концепт-граф
чтение:    Δ_c = Σ_s σ_read(s)·w(U_s)·W_o·(m_s + Σ_g G_k[s,g]·h_K^g)
           # концепт вплетается в сигнал с учётом того, какие эксперты его несут
```

**Гейт чтения = «используй концепт только когда основной сигнал недотянул»** (проверено
на прототипе Mini, `core/concept_layer.py`):

```
Δ_c = W_o(Σ_s a_s·w(U_s)·m_s) · σ_u · σ_c · scale

σ_u = sigmoid(κ·(‖pred_err‖ − θ))   # гейт НЕУВЕРЕННОСТИ: открыт, когда основной слой
                                    # плохо предсказал себя (модель сама сообщает
                                    # «данных слоя недостаточно»)
σ_c = sigmoid(γ·(cos(Δ_c, h_ctx) − τ_c))  # гейт ПРОТИВОРЕЧИЙ: концепт пускается в ход,
                                    # только если он согласован с текущим контекстом.
                                    # «Розовый слон» (лакуна «у слона нет описания цвета»)
                                    # не проходит: рождённый-но-неподтверждённый слот
                                    # расходится с контекстом → σ_c → 0.
scale = sigmoid(learnable)          # модель сама учится доверять концептам
```

Ключевое отличие от «просто ещё одного слоя»: запись идёт всегда (зрелый слой, уверенные
+ новизнные состояния), но **чтение — только при нехватке основного сигнала и отсутствии
противоречия**. Это и есть защита от «изобретения ядерного реактора»: лакуна провоцирует
рождение, но разумный процесс никуда не пускает его, пока нет подтверждения. Рождение —
это не факт, а *вопрос*; ответ — согласованность с контекстом и вклад в loss.

**Новые обучаемые параметры (на тех же данных):**

```
Main: W_o (S·k→D) ≈ 524K + G_k (S·G) ≈ 256 + гейты ≈ 8    ≈ 0.03% от 255M
Mini: ≈ 114K                                              ≈ 0.08% от 17.6M
```

**Почему «новые параметры на том же объёме данных» — это честный, но тонкий тезис:**
ценность не в объёме (0.03–0.08% — ничто), а в **структурной агрегации**:
- базовый вес обучается одним примером (1 токен/параметр);
- концепт-слот обучается **всеми токенами, которые его активируют** — сотни примеров
  льются в один прототип;
- значит у концепта «эффективных данных-на-параметр» на порядки больше, чем у базового веса.

То есть это **механизм эффективности данных**, а не ёмкости. Наивное раздувание слота
в большой MLP вернуло бы стену переобучения (478M токенов / 255M параметров). Слой
оправдан только если абляция показывает выигрыш по val_loss.

**Синергия с 6.1 (один языковой орган):**
- формализация слота (декод) = «голос» слоя концептов;
- dive может эмитить/потреблять **имена** концептов — перекрёстно-слойные ссылки по токену;
- верификация противоречий декодирует состояния экспертов — тот же `Head`/`E`.

**Аналог в EVA:** `G_k` + `C` — это knowledge/concept graph (в mirror уже есть зародыш:
`_concept_sim_ema`, `_behavior_div_ema`, `_trust_matrix`, `mirror.py:151-153`), только на
уровне концептов, а не экспертов.

## 7. Опциональный роутинг (не обязательно прогонять сигнал)

Чтение коллективного слоя — через learnable-гейт `σ(g_l)` (per-token, как в `mirror.py:497-505`):

- жёсткий бинарный гейт недифференцируем → не используем
- мягкий sigmoid-гейт + **sparsity-давление** (`gate_l1`) на `σ(g_l)`, иначе «градиентная
  река» откроет гейт всегда и опциональность станет номинальной
- модель сама выбирает, на каком слое/токене консультироваться с коллективом

## 9. Метрики и валидация

Числа для эксперимента (7+1):

1. **Профиль `σ(g_l)` по глубине** — ждём рост с глубиной
2. **Рождение слотов во времени** — пик в начале, затем стабилизация
3. **Средняя лакуна `Δ̄`** — должна падать по мере заполнения дыр
4. **Концентрация занятости** (HHI по `U_s`) и **SV-спектр слотов** — коллапс = дисперсия → 0
5. **Декод-проба (диагностика)**: топ-k «имён» рождённых слотов; доля реальных слов по
   словарю + энтропия имени. Witness — не критерий истинности (см. 4.5/4.6).
6. **Само-суждение (3 критерия 4.6)**: консистентность активации, вклад в loss,
   устойчивость `U_s` — какая доля рождённых слотов доходит до `stable`
7. **Концепт-граф (6.2)**: плотность/степень распределения `C`, спарсность `G_k`
   (сколько экспертов на концепт — полиамория vs монополия), вербальный гэп `ρ_l`
   по глубине (должен падать по мере обучения)
8. **Абляция**: (a) baseline private_mem, (b) коллективный слой forced-read,
   (c) коллективный слой gated-read, (d) + концепт-экспертный слой → если (d) ≈ (c)
   по val_loss, слой концептов — мёртвый вес и его выкидываем

### 9.1 Синтетическая проба (контролируемый тест цепи)

Цель — проверить readout-цепь на ожидаемом слове, без большой генерации:

```
ПРОБА: контекст {собака, лает} → mirror → коллективный readout → head → top-k → декод
PASS:  в top-k есть «громко» (сильнейший приоритет коллокации)
       или модальное наречие {громко, злобно, яростно, громче} (смягчённый PASS)
FAIL:  в top-k мусор/несвязанные слова
```

Важные оговорки:
- это тест **ретрива/предсказания**, а не рождения: «громко» уже в словаре, лакуны нет;
  майнер тут не рождает, а выводит связанный концепт через слот
- PASS по top-k, не по argmax: полный триграмм «собака лает громко» в корпусе редок
- **сравнение с baseline без коллективного слоя**: если top-k с коллективом не лучше,
  слой не платит за себя
- лексическая верификация противоречий (6.1) может подтверждать/опровергать disagreement:
  декодированные слова экспертов конфликтуют → lexical contradiction (скаляр в арбитр, no_grad)

Самокуррикулум (опционально, этап 5): декодированное реальное слово рождённого слота
можно вернуть в обучение как редкий самосгенерированный сигнал. Осторожно: свободная
самогенерация ведёт к коллапсу; допустим только спарсный, словарно-проверяемый сигнал.

## 10. Риски и митигации

| Риск | Митигация |
|---|---|
| Рождение мусора (novelty фиксирует шум) | рождение только при устойчивом `N_gap` + валидация токенизатором (3); влияние гейтованное уверенностью `U_s` |
| Схлопывание слотов | репульсия + soft-competition записи |
| Концепт-граф → «клуб» (немного концептов монополизируют связи) | `λ_bal_concept` (энтропия на `a_s`), спарсность `G_k` |
| Эхо-камера | write-delay, малый `α_c`, контрактивность оператора записи |
| «Везде открыто» = переобучение | sparsity-давление на гейт чтения; `scale` (sigmoid) сам ограничивает доверие |
| Модель выдумывает «розовых слонов» (рождение на лакуне без подтверждения) | гейт противоречий `σ_c`: рождённый слот в ход не пускается, пока не согласован с контекстом; формализация токенизатором |
| Rank-коллапс от `L_rt` (состояния в подпространство эмбеддинга) | малый `λ_rt`, контрастный негатив, только слои dive, после warmup |
| Слой концептов не платит за себя (≈ gated-read) | абляция (d) → выкидываем |

## 11. План реализации (порядок работ)

1. **Baseline 86M на T4** (чистые данные) — доказать обучаемость. Без этого механизм не имеет смысла.
2. **Прототип на Mini** — сделано: `core/concept_layer.py`, флаг `--collective-layer`
   (слой L6), зонд `scripts/probe_concepts.py` (readiness + gap + decode-probe). Сборка
   проходит, NaN нет, рождения после зрелости подтверждены юнит-тестом.
   Следующее: полный прогон Mini с механизмом против baseline.
3. **Сбор 8 метрик** (раздел 9) по шагам, сравнение абляций (a/b/c/d).
4. Только если gated-read выигрывает по val_loss — перенос в Main и обучение с механизмом.
5. **Декод-проба** рождённых слотов: только диагностика, никакого влияния на обучение.
6. **Синтетическая проба** (раздел 9.1): контекст {собака, лает} → top-k → декод;
   сравнение с baseline без коллективного слоя.
