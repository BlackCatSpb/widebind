## Архитектурные принципы саморегуляции (зафиксировано в коде)
1. **Ошибка предсказания зеркала** (`mirror.py:270-294`) — `pred_error = (hp - pred_k)/||hp||` масштабно-инвариантна; `pred_error_norm` → `pen`, модулирует гейты/decay в блоке.
2. **α-самонастройка временны́х шкал** (`mirror.py:298-318`): `alpha_target = sigmoid(2.2 - log(relative_var))` → шумное измерение получает короткое τ (забыть), предсказуемое — длинное (помнить).
3. **Переслойная LR-модуляция** (`stack.py:1198-1229`, `_update_ls_mult`): `ratio = fast/slow EMA var(log_scale)`; растущая дисперсия слоя → его градиенты прижимаются (нет взрыва на слое).
4. **Глобальный LR — контрциклический** (`stack.py:1276-1324`): `mult = clamp((var_mult·α_mult·gate_mult)^⅓ · mag_factor · loss_lr_factor, 0.05, 1.0)` — **всегда ≤ базы**, только душит.
5. **Коллектив сам выбирает что помнить** (`concept_layer.py`): запись при `mature≥0.5` И `conf≥медианы` И новизне. Его `write_event` → сигнал границ слов для прожектора.
6. **Reasoning адаптивной глубины** (`reasoning.py:106-152`): `max_steps=8` — **потолок**, не счётчик. `ReasoningGate` инициализирован 1 шагом открытым, остальные закрыты; модель учится открывать глубину per-token через сигнал знания `know` и кандидата `r`; цикл останавливается при `gate < stop_threshold`.

## Целостность конвейера данных (проверено 2026-08-21)
Вопрос: не режет ли нарезка бинарников предложения так, что разметка портится?
**Ответ: нет, разметка не портится.** Доказательство по коду:
- EOS вшивается на границах предложений (`build_streams_eos.py:114-116,141-154`, формат `[EOS]+sent+[EOS]…`), и `get_batch` (`colab.ipynb:265-272`) читает **непрерывный слайс** `data[offset:offset+needed]` без репаковки → EOS на своих местах.
- `state` переносится между окнами (`colab.ipynb:424-428`: сброс `state=None` ТОЛЬКО при `offset==0`, т.е. на границе файла). Внутри файла окна континуальны → предложение на стыке окон видно непрерывно, **фантомных границ каждые 256 токенов нет**. Сброс только на стыке файлов (новый документ) — редко и семантически верно.
- Предложения короткие (min 3 слова, `build_streams_eos.py:27`, ~15-25 токенов) → ~10-17 целых предложений с EOS в каждом 256-окне. `mask_eos=False` (cell 138) — EOS обучаем, согласован с `*_eos.bin`.
- Для Прожектора: границы слов берутся из `concept_layer._write_event` (обучаемый сигнал по новизне), а не из EOS напрямую; контекст внутри файла непрерывен → границы не фантомные.
- Оговорки: (А) сплиттер `split_sentences` эвристический — не ловит диалоговые тире/многоточия/цитаты, аббревиатуры частично; исходная разметка местами шумит (вопрос `build_streams_eos.py`, не seq_len). **Инсайт (пользователь, 2026-08-21): этот шум — плюс.** Архитектура учится по ошибке предсказания (`mirror.py:270-294`), поэтому нечёткая разметка даёт естественный контраст «где граница достоверна / где сомнительна»; зеркала/эксперты сами калибруют τ и α под неопределённость. Чистая разметка была бы слишком лёгкой и лишила бы модель сигнала о собственных ошибках понимания границ. (B) стык файлов режет редкое длинное предложение — ничтожно редко. (C) нет BOS в начале окна (кроме 1-го токена файла) — стандарт LM.
- Опция: скрипт подсчёта EOS/окно на выборке (бинарники на Drive) для эмпирического подтверждения (~10-17, не 0).
