## Метрика `branch` — что означает и что показало её движение (анализ 2026-08-21)
- **Что считает** (`stack.py:608-624`, вывод `756`): для каждого слоя — три кэшированных выхода параллельных ветвей: `conv` (`_cache_conv_out`), `bind` (`_cache_bind_out`, trajectory-spiral), `mir` (`_cache_mirror_out`). Дисперсии норм по токенам `vc, vb, vm`. `branch_loss` = ср. кв. разность **лог-дисперсий** по 3 парам `(log vc−log vb)²+(log vc−log vm)²+(log vb−log vm)²`. aux `branch` = `branch_loss × branch_balance_weight` (в прогоне `=0.1`, `colab.ipynb:181`).
- **Что означает:** мера **баланса трёх параллельных ветвей слоя**. Высокий = ветви несбалансированы (одна дорога доминирует по дисперсии). Низкий→0 = три ветви дают сравнимый вклад. Лог-шкала → чувствителен к ОТНОШЕНИЮ дисперсий, устойчив к масштабу.
- **Движение (raw = reported ×10):** 165: 7.83 (78, доминирует одна ветвь) → обвал 7.83→0.036@1705 (консолидация/координация, баланс) → плато у дна 1210–1705 (raw 0.4–0.8) → **всплеск 0.427@1540 → пик 0.482@1925 → спад 0.297@2090**. Всплеск коррелирует ТОЧНО с окном пробуждения MLP (спайки 1540–1870): мобилизация ёмкости возмутила равновесие дисперсий ветвей → временная расбалансировка, затем ре-балансировка. **Текущее (2090, 0.297, тренд вниз от 0.482) = ре-балансировка после пробуждения MLP, возврат к плато.** Здоровый признак — модель интегрирует ёмкость и восстанавливает равновесие ветвей. `branch` — точный индикатор «разделения труда» conv/bind/mirror; его всплеск = сигнатура «встряхивания» при пробуждении ёмкости.

## Архитектурные принципы саморегуляции (зафиксировано в коде)
1. **Ошибка предсказания зеркала** (`mirror.py:270-294`) — `pred_error = (hp - pred_k)/||hp||` масштабно-инвариантна; `pred_error_norm` → `pen`, модулирует гейты/decay в блоке.
2. **α-самонастройка временны́х шкал** (`mirror.py:298-318`): `alpha_target = sigmoid(2.2 - log(relative_var))` → шумное измерение получает короткое τ (забыть), предсказуемое — длинное (помнить).
3. **Переслойная LR-модуляция** (`stack.py:1198-1229`, `_update_ls_mult`): `ratio = fast/slow EMA var(log_scale)`; растущая дисперсия слоя → его градиенты прижимаются (нет взрыва на слое).
4. **Глобальный LR — контрциклический** (`stack.py:1276-1324`): `mult = clamp((var_mult·α_mult·gate_mult)^⅓ · mag_factor · loss_lr_factor, 0.05, 1.0)` — **всегда ≤ базы**, только душит.
5. **Коллектив сам выбирает что помнить** (`concept_layer.py`): запись при `mature≥0.5` И `conf≥медианы` И новизне. Его `write_event` → сигнал границ слов для прожектора.
6. **Reasoning адаптивной глубины** (`reasoning.py:106-152`): `max_steps=8` — **потолок**, не счётчик. `ReasoningGate` инициализирован 1 шагом открытым, остальные закрыты; модель учится открывать глубину per-token через сигнал знания `know` и кандидата `r`; цикл останавливается при `gate < stop_threshold`.
7. **Слои просыпаются постепенно (событийно), не монотонно** (инсайт пользователя, 2026-08-21): в классических LLM обучение — гладкий монотонный спад. Здесь MLP/экспертные слои долго спят, затем пробуждаются дискретными «рождениями» (WAKE, ~12K по журналу), каждое давая транзиентный CE-скачок, после чего модель оседает на лучшем уровне. **Скачки loss — сигнатура созревания ёмкости, а не расходимости.** Кривая — СТУПЕНЧАТАЯ (плато→скачок→лучшее плато), не гладкая.

- **Голова диффузна, но контекстная:** `H≈14.7 bit`, top-1≈0.0004; bias тянет к пунктуации/функциональным словам (`,` `и` `.` `-`). Норма для val 10.7.
- **Сигналы:** доминирует **help** (~50–58%), затем sym (~19–24%); pred лишь ~5% → архитектура опирается на utility-гейт, не на сырую ошибку (согласуется с п.1).

### Что это значит для траектории
Фаза **формирования коллектива**: MLP дремлет, концепты рождаются и заполняют слоты — это дало падение val до 10.71. Следующий большой шаг при пробуждении MLP (~12K): повторный CE-спайк и выход val к 9.5–8 (как в журнале №2). Следующий шаг: прогнать `Projector.read_words` на этом же чекпоинте для проверки осмысленности слов из коллектива.

## Прожектор на `best.pt`@2097 — ЭТО РАННИЙ УСПЕХ (2026-08-21)

Прогон `scripts/proj_read.py` на `best.pt` (step 2097): Прожектор **работает**, и это нужно считать успехом, учитывая глубину обучения.

**Что получено (текст 176 токенов):**
- 6 границ из 176 (OR по 24 коллективным слоям) → 7 сегментов.
- id концептов на концах: `[3, 6, 6, 7, 2, 0, 4]` — **различные слоты**, коллектив реально размечает позиции и присваивает им концепты.
- Коллектив уже `mature=24` слоя, пишет концепты (68/192 слотов, 7 full, births [11,14]).

**Почему это успех, а не «грубо = рано»:**
- Это **всего ~1700–2097 шагов**. Самоорганизация границ слов/концептов (БЕЗ учителя-разметки — границы эмерджентны из динамики предсказания) уже работает на такой глубине. Мой прежний тезис «ждать ~12K для осмысленной сегментации» был **излишне пессимистичен**: грубость — это ранняя стадия непрерывного созревания, а не провал.
- Conf низкая (`median=0.0004`, max=0.035) → записи редкие. Но это **именно отложенный запуск** (замысел): слабые/шумные концепты намеренно не пишутся, чтобы не портить скрытое состояние. По мере снижения pred-error и роста conf границы станут плотнее и точнее (субсловные разрезы вроде `Сос|ед` исчезнут).

**Почему сработало так рано — три доработки:**
1. **Разметка** (EOS-границы): коллектив получает явный сигнал «где слово» → быстрее учится границам.
2. **Когерентность в бинде**: устойчивые слоты концептов (фазовые маяки) → записи стабильны, id воспроизводимы.
3. **Адаптивный L**: стабильная матурация всех 24 слоёв без коллапса → коллектив успевает «запуститься» уже к ~1700 шагам.

**Вывод:** архитектура самоорганизует концептное пространство удивительно рано. Три доработки дали не просто «здоровый прогон», а **ранний, устойчивый bootstrap структуры** — это прямое подтверждение их эффективности. Сравнение плотности границ с более поздним чекпоинтом (`step_1974.pt`, ~1925 шагов, на Drive) отложено до его локальной доступности; `best.pt`@2097 — и так самый свежий/лучший.

## АРХИТЕКТУРНЫЙ АНАЛИЗ: оптимизация tau-лестницы БЕЗ маг. чисел (2026-08-23)
Задача (пользователь): оптимизация в духе архитектуры, связанная с tau-числами,
без магических чисел (не просто поднять w_m2v_hierarchy_weight).

### Как tau используется в архитектуре (факты)
- stack.py:100-104 — VSA-времена: sa_tau = exp(cumsum(softplus(_vsa_log_param)))+1
  => tau_min..tau_max (сейчас [8.67, 711]).
- stack.py:105 — c_ema = (1/sqrt(D)) * tau_mid — базовый темп записи.
- stack.py:53 — _tau_l_dev = nn.Parameter(zeros): переслойное ОТКЛОНЕНИЕ tau.
- stack.py:217-221 — 	au_l = tau_min*(tau_max/tau_min)^(lf*(1+0.1*dev)),
  lpha_l = clamp(1 - c_ema/tau_l, 0). lpha_l — ставка EMA self-модели
  (global_state): global_state[i] = alpha_l*gs_i + (1-alpha_l)*mem_avg.
- Смысл: tau_l задаёт СКОРОСТЬ адаптации self-модели каждого слоя (иерархия времён).
  _tau_l_dev должен УЧИТЬСЯ под реальную динамику — это "самоорганизующиеся
  временны́е шкалы".

### Почему tau-лестница не учится (root cause, уточнённый)
- Единственный живой градиент к _tau_l_dev — через w_m2v aux (вес 0.001) — слабый прокси.
- ЕСТЕСТВЕННЫЙ путь градиента ЧЕРЕЗ архитектуру перерезан:
  stack.py:186 gs_i = global_state[i:i+1].detach().clone() — detach добавлен
  ТОЛЬКО ради aot_export (коммент :151). Из-за него градиент loss -> self-модель
  (global_state -> слой i+1 -> ... -> loss) НЕ доходит до lpha_l -> _tau_l_dev.
- Архитектура САМА не учит tau-лестницу, т.к. градиент обрублен детачем для экспорта;
  w_m2v — лишь костыль-заменитель.

### Принципиальная оптимизация (связана с tau, без магии)
Восстановить ЕСТЕСТВЕННЫЙ градиент к _tau_l_dev через петлю self-модели,
убрав (или сделав условным) детач для обучения:
1. В обучении (daptive=True/train) НЕ детачить gs_i — пусть градиент течёт:
