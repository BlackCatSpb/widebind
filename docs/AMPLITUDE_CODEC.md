# SignedAmpCodec: итоги батареи (margin + argmax-hinge + W_pred)

Дата: 2026-08-04. Экспериментальный цикл завершён; все результаты воспроизводимы
`scripts/mini_amp.py` (V=64 → 3.6 steps/s на GPU MX550).

## Зачем

Штатная головка WideBind использует softmax/CE. Экспериментальная головка
`SignedAmpCodec` убирает softmax и считает плотность по K амплитудным осям:

```
запись:  h = rope( Σ_k α_vk · basis_k ) · scale,   α_vk = tanh(proto[v,k]) · codes[v,k]
чтение:  a = tanh(gain · W_pred ⟨h_L, basis⟩)      (контекстный канал)
         p = gain_emb · ⟨h_emb, basis⟩              (код-канал, эхо записи)
счёт:    s(v) = Σ_k log N(a_k; α_vk, σ_on) + Σ_k log N(p_k; α_vk, σ_emb) − токен-байас
цель:    margin = −(logP(target) − E_q logP)   q = плотность по всем токенам
         hinge  = max(0, s(w*) − s(y)),        w* = argmax_{w≠y} s(w)
         reg    = ‖a − α_y‖² по активным позициям (механизм C, необязателен)
оптимизатор: AmpAdam (head/embed/backbone группы, коробки gain∈[0.1,4], σ∈[σ_min,1])
```

Коды — sparse (случайное активное подмножество, `code_sparsity`), строки базиса
единичной нормы (чтение = α без аттенюации), gain init 0.5 против насыщения tanh.

## Диагностика (что сломано без изменений)

- Margin-only вырождается: 1500 шагов → margin −22.8, top1 0%, α→0.041.
  **Причина:** цель против E_q не ограничивает argmax (margin −4.6 при top1 34%).
  → лечение: `argmax_hinge` против истинного argmax-конкурента (O(V·K), без softmax).
- Шум стека топит код: проекция финального слоя std≈2.85 против кода std≈0.095
  (в 30 раз). С диагностикой corr: **copy 89%** только после hinge.
- `pure-read` (стек заморожен, код-канал): 67→78% с шага 1, backbone grad 0.00 —
  кодек читает свою запись идеально; всё ограничение было в шуме стека.
- σ-пол: σ∈[σ_min,1] обязательно (σ_min=0.2 по умолчанию; margin требует σ_min>0).
  Раннее снижение пола (0.1) НЕ помогло — сигмы и не доходят до пола (0.29 на 2500).

## Выводы

1. **W_pred (механизм A) — победитель.** K×K оператор перехода в кодовом
   пространстве, init I+0.01·randn (в init тождественен отсутствию pred —
   нулевая дестабилизация), применяется к контекстной проекции ДО tanh·gain.
   Это прямое воплощение TransitionManifold из FCF: переходы живут в кодовом
   пространстве (`T = unbind(v_next, v_prev)`).
2. **code_reg (C) полезен ТОЛЬКО поверх A** (+1.5 pt); без A — вредит (−12.5 pt):
   плотная регрессия к цели конфликтует с острым argmax-разделением.
3. **Фазоры (корни из единицы)** дают переход-вращение идеально (corr чтения
   0.93 против 0.8 у sparse), но плотный низкоранговый код не разделяет соседние
   токены в argmax (top1 17% при margin −260). Sparse-коды разделяют, а вращение
   выучивается и так — линейным W_pred. Фазоры остаются диагностическим
   инструментом (доказывают обучаемость вращений).
4. **hybrid (sparse+phasor в одном коде)** — отрицательный: фазовые позиции
   (26 шт., α=0.8) на порядки доминируют в счёте над sparse (6 шт., α=0.2),
   margin застревает на −2.5, top1 ~0%.
5. **Перенос на реальный масштаб:** copy V=1024 600 шагов: 89.06% → **93.75%**
   (A+C). Без регрессии copy V=64: 98.44% = 98.44%.
6. Стабильность: ни одного NaN во всех конфигурациях батареи; α_std медленно
   дрейфует вниз (0.115→0.061 за 2500) — для очень длинных прогонов желателен
   нижний предел амплитуды кода (TODO).

## Математическое упрощение (2026-08-04): одна цель CE вместо margin+hinge+reg

Структура факторизованного счёта: `s(v) = Σ_k[z·logN(a;α_vk,σon)+(1−z)·logN(a;o,σoff)] + эхо + bias(v)`.
Три кандидата-цели:

- margin = E_q[s] − s(y)  (зазор до среднего)
- hinge  = max(0, s(w*) − s(y)), w*=argmax_{v≠y}  (зазор до argmax)
- **CE = logΣexp(s) − s(y)**

Тождества: `CE = hinge + log(1+Σ_{v≠w*}e^{s(v)−s(w*)}) ≥ hinge`, и
`CE = margin + [logΣexp(s) − E_q s] ≥ margin` (неравенство log-sum-exp). CE
доминирует обе цели: борется с argmax-конкурентом И требует остроты (член ≥ 0 —
именно его не хватало margin-only, из-за чего коллапсил α). CE ≥ 0 всегда
(нормировка мягкая), admissibility-ограничение σ не нужно, O(V·K) — без удорожания.

**Батарея CE (counter V=64, 1500 шагов):**

| Цель | 400/1500 top1 |
|---|---|
| margin+hinge+pred+reg (старый победитель) | 26.6% / 85.9% |
| CE base | — / **85.9%** (без pred = старый трёхцелевой!) |
| CE + pred | 35.9% / **93.75%** (mh+pred+reg достигал этого только к 2500) |
| CE + pred + reg | 93.75% (reg нейтрален — не нужен) |
| CE + pred, без эхо | 90.6% (эхо даёт +3pt — мягкий якорь счёта) |

Перенос: **copy V=1024, 600 шагов: CE+pred = 96.88%** против mh+pred+reg = 93.75%.

**Что упрощается:** одна цель `ce_loss` вместо margin_loss+argmax_hinge(+code_reg);
нет hinge_weight; избыточная E_q-машинерия (μ,ν,p-статистики) не нужна для обучения;
σ при CE РАСТЁТ (0.31→0.34 — острота идёт из счёта, а не из дрейфа σ). Сбоку:
`project_mean` в AmpAdam избыточен (центрирование bias в forward уже обнуляет
среднее градиента по цепному правилу), σ/gain-коробки уже head-side (в `_sigmas`/
`_amps` на time forward), поэтому кодек совместим с любым Adam-оптимизатором.
