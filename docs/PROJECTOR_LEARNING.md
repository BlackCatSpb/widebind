# PROJECTOR LEARNING — обучаемый прожектор на числовых профилях

Статус: дизайн (реализация не начата). Связан с docs/WORD_ARITHMETIC.md (§8).

## 1. Принцип

Правила (rule-based `sentence_builder`) остаются только baseline и генератором
синтетических учительских примеров. Конечная логика прожектора — **обучаемые
компоненты WideBind-семейства**: гейт маршрутизации, эксперты-агрегаторы,
арбитр-декодер порядка, слои концептов. Все они обучаются с нуля на числовых
профилях слов (см. WORD_ARITHMETIC §8.1) + признаках трафарета.

## 2. Компоненты

### 2.1 Профиль слова (вход)

Для каждого слова-кандидата w:

    P(w) = concat(
        F(w)        # факторный вектор 33 (степени простых φ)
        log N(w)    # лог-размер состава
        V(w) mod B  # позиционная подпись
        M(w, t)     # морфо-близость к соседям кандидатам
        salience    # λ-глубина, POS-onehot, тема-доля, PMI-вектор из трафарета
        embed(w)    # эмбеддинг WideBind (замороженный, путь A)
    )

### 2.2 Гейт маршрутизации

`gate: P(w) → распределение по экспертам` (softmax). Учится специализации:
слова с общим делителем (общий корень/морфо-группа) → один эксперт;
служебные (малые N) → другой; ядровые (большие N) → третий.
Инициализация: k-means по факторным векторам (кластеризация НОД-структуры).

### 2.3 Эксперты-агрегаторы

`expert_g: {P(w)} → аггрегат группы` (внимание по морфо-близости внутри группы).
Эксперт выбирает «центр» (ядро: предикат) и кандидатов-актантов — учится
воспроизводить валентностные рамки (учитель: verb_frames трафарета).

### 2.4 Арбитр-декодер (порядок слов)

`arbiter: (профили группы, состояние) → следующий индекс` — pointer network
или трансформер-энкодер над профилями + авторегрессивный выбор. Учится на
реальном порядке слов корпуса (teacher forcing). Вход шага: профили оставшихся
слов, позиция, роль последнего выбранного. Выход: мягкое распределение по
индексам → argmax.

### 2.5 Слои концептов

`CollectiveConceptLayer` WideBind переиспользуется: концепт = обучаемый
центроид в пространстве профилей; инициализация по делимости (слова с общим
делителем → общий концепт); эмиссия концепта → выбор слова-члена группы
(первый шаг арбитра). Это естественный мост: WideBind-слои концептов уже
оперируют на h.

## 3. Данные и обучение

### 3.1 Учитель

- **Реальный порядок**: предложения `corpus_1m.txt` → токенизация (pymorphy3) →
  пары (мультимножество слов, правильная последовательность).
- **Валентность**: verb_frames трафарета как учитель для выбора актантов.
- **Согласование**: pymorphy3 — детерминированный финальный шаг (не обучаемый).

### 3.2 Лоссы

    L = L_order (кросс-энтропия порядка арбитра)
      + λ₁·L_gate (кластеризация групп по реальным группам корпуса)
      + λ₂·L_frame (валентностные рамки: актант/не-актант BCE)

### 3.3 Метрики (лестница этапов)

Декодирование → связность (PMI) → грамматичность (морфо-проверка ≥90%) →
осмысленность (ядро+актанты, 7–9 слов, тема-рема) → автономный EOS.
Baseline сравнения: rule-based `sentence_builder`.

## 4. Совместимость с прогрессом обучения

**Путь A (рекомендуется сначала):** новый модуль `projector_net` обучается
отдельным скриптом `train_projector.py`; WideBind эмбеддинги заморожены.
Чекпоинты WideBind, Colab-обучение, `core/stack.py` не затрагиваются.
Прогресс обучения (step 15844, best 8.2239) сохраняется.

**Путь B (полная интеграция, перезапуск обучения с нуля):** числовые профили
встраиваются в `core/embedding.py`/`core/block.py` (входы экспертов и гейтов
GroupedCognitiveMirror, слои концептов). Ломает state_dict → новый чекпоинт,
обучение с нуля. Перед перезапуском собрать пакет доработок:
1) EOS-обучение (не маскировать в CE);
2) чистка/нормализация данных (OCR-шапки, «пер. Салье»);
3) φ-профили в эмбеддинги;
4) слои концептов на числовой инициализации.

Порядок: сначала A (валидация гипотезы: обучается ли порядок по профилям),
затем B (если A показывает связность на лестнице этапов).

## 5. Единый процесс обучения (путь B)

Решение: полная интеграция и перезапуск обучения с нуля. Всё обучается
**в одном процессе** (один цикл, один оптимизатор, совместные представления).

### 5.1 Схема шага

    батч токенов (бинарники)      батч предложений (corpus_1m.txt)
              │                              │
              ▼                              ▼
   WideBind (эксперты, гейты,     профили word_num (CPU/numpy, вне графа)
   слои концептов, EOS-головка)        │
              │                        ▼
              ▼              головки прожектора: гейт(роли, BCE)
         L_lm (CE + EOS)             + арбитр(порядок, BCE) → L_struct
              └───────────┬───────────┘
                          ▼
               L_total = L_lm + λ·L_struct  → 1 backward, 1 шаг Adam

### 5.2 Ключевые решения

1. **Два даталоадера** в одном цикле: бинарники (токены, L_lm) и текст
   (предложения 7–12 слов, L_struct). Чередование: структурный батч каждый
   N-й шаг (N — гиперпараметр, старт N=4).
2. **Профили вне автографа**: numpy/collate (как в train_projector.py),
   в граф попадают только головки (гейт/арбитр) поверх h WideBind.
3. **EOS-обучение** в L_lm: границы предложений из текста; CE по EOS-токену
   не маскируется (снимается маска PAD/EOS из stack.py:439).
4. **φ-признаки в эмбеддинги** (embedding.py): конкатенация факторного
   вектора → смена state_dict → обучение с нуля (согласовано).
5. **Головки**: встраиваются в WideBindBlock/stack.py как опциональные модули
   (флаг `projector_head`), выходы — h слоя, учителя — порядок слов и роли.
6. **Чистка данных**: OCR-шапки/«пер. Салье» из корпуса перед генерацией
   бинарников (обновление pipeline FCF).
7. **Учительские роли** для гейта: rule-based разметка (sentence_builder +
   POS pymorphy3) — как в make_supervision.py; арбитр учится на реальном
   порядке корпуса (teacher forcing).
8. **Морфосогласование** — pymorphy3 на выходе (детерминированный финал,
   не обучаемый), как сейчас.

### 5.3 Метрики в процессе

Лестница этапов (декодирование → PMI → морфо → ядро+актанты → EOS) +
acc1/accfull/lcs арбитра (валидационный батч каждые K шагов).
Baseline — rule-based sentence_builder и текущий train_projector (путь A).

### 5.4 Совместимость

Полный перезапуск: чекпоинты предыдущих прогонов несовместимы
(изменение embedding + головки + EOS-маска). Прогресс Colab
(step 15844, best 8.2239) архивируется как референс, не восстанавливается.

## 6. Этапы реализации

1. `core/projector_net.py` — профили, гейт, эксперты, арбитр (torch, без WideBind-зависимости).
